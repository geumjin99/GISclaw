# ADR-003 · Win / mac 原生安装包的分发方案

- **状态**: 决定 (Decided) — 2026-09-01 按 B 实施：uv 管理的可搬迁 Python 装进包内，pywebview 窗口，macOS .dmg（ad-hoc 签名）+ Windows Inno Setup .exe，GitHub Actions 出包
- **日期**: 2026-09-01
- **作者**: Han Jinzhen

## 背景
v1.0 只能 `docker compose up`。Docker Desktop 本身就是门槛（下载、虚拟化、内存分配、公司电脑装不了），16 GB Mac 上还会吃掉 4–8 GB。目标是「下载 → 双击 → 出窗口 → 能用」。难点在于 GIS 栈（GDAL / GEOS / PROJ + rasterio / fiona / pyproj / shapely）与沙箱：沙箱执行的是模型现写的任意 Python，会 `import` 任何已装的包。

## 选项
| 方案 | 优点 | 缺点 |
|---|---|---|
| A. PyInstaller 把整个应用冻结成一个包 | 单一产物、纯 Python 工具链 | GDAL / PROJ 数据文件 hook 脆弱；**冻结只收静态分析到的模块，模型写的代码 `import` 一个没被收进去的包就崩**；1 GB 级、启动慢 |
| B. 完整 Python 环境随包（python-build-standalone + 用 uv 预装 PyPI wheel）+ 只冻结一个几十行的 pywebview 启动器 + Inno Setup / create-dmg 出安装包 | 真实 `site-packages`，模型代码想 import 什么都在；GIS 栈来自 PyPI 二进制 wheel（rasterio / fiona / pyproj / shapely 均自带 GDAL / PROJ 数据），**不再需要 conda**；启动器极小，PyInstaller 只碰它 | 安装包 700 MB–1 GB；无内建自动更新 |
| C. Tauri v2 壳 + Python 环境作 sidecar | 壳 10 MB、自带 updater、`tauri-action` 一键出签名包 | 多一个 Rust 工具链；对纯 Python 维护者是新负担 |
| D. Electron + uv（ComfyUI Desktop 路线） | 成熟先例 | 壳 150 MB 起，与 C 相比无优势 |

## 决定（提案）
**B**，分两步落地，第二步复用第一步的全部产物：
1. **v1.2 先做「无 Docker 脚本安装」**：`install.sh` / `install.ps1` 用 uv 装 Python 3.11 + venv + wheel，`gisclaw` 命令起服务并打开浏览器。这一步验证 PyPI wheel 路线在 Win / mac 上是否真能装齐（PROJECT.md 有一条待验证项）。
2. **v2.0 把同一个环境打进安装包**：python-build-standalone 替代系统 Python，pywebview 出原生窗口（Win 用 WebView2，mac 用 WKWebView），Inno Setup 出 `.exe`、create-dmg 出 `.dmg`，GitHub Actions 矩阵构建、上传 Release。
3. **端口与数据**：启动时挑空闲端口而不是写死 8765；工作区默认放用户目录（Win `%LOCALAPPDATA%\GISclaw`，mac `~/Library/Application Support/GISclaw`），不放安装目录。
4. **字体**：不带 100 MB 的 Noto CJK，改为按系统选（Win：Microsoft YaHei / Malgun Gothic；mac：PingFang SC / Apple SD Gothic Neo），matplotlib rc 在启动器里按平台写。
5. **安全边界（E4，v1.2 前置）**：原生模式没有容器隔离，模型代码以用户身份跑。至少做到：沙箱 cwd 锁在项目目录、`code.py` 落盘可审、DISCLAIMER 与首次启动对话框明说；涉密数据仍推荐 Docker 模式。
6. **签名**（B2）：mac 必须 Developer ID + 公证，否则用户看到「已损坏」；Windows 先接受 SmartScreen 警告并在手册写清，签名证书视用户量再上。

若日后要自动更新与更精致的安装体验，再迁到 C（Tauri）；B 的 Python 环境目录可原样作为 Tauri 的 resources 复用。

## 理由
决定性的一条是沙箱：只有「真实 site-packages」才能让模型写的代码想 import 什么都能成功，A 在这里是结构性不可行。B 全程 Python，维护成本最低；C/D 的收益（updater、小壳）不是现阶段瓶颈。

## 结果
安装包体积大（与 QGIS 同量级）是接受的代价。`Dockerfile` 保留，Docker 模式成为「隔离运行」选项而非唯一路径。
