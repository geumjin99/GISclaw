# ADR-002 · 界面多语言（en / zh / ko）方案

- **状态**: 提案 (Proposed)
- **日期**: 2026-09-01
- **作者**: Han Jinzhen

## 背景
界面是纯英文（`index.html` 约 113 个文本节点，`app.js` 约 80–150 条运行时字符串，`server.py` 若干经 SSE `status` 事件与 HTTP `detail` 送到界面的英文句子）。README 与 PDF 手册已三语，界面是唯一还没本地化的一层。前端是无框架 vanilla JS，没有现成 i18n 机制。agent 侧 `reflect.py` 已要求「用用户提问的语言作答」，但 run 收尾的 closing note、`LOG.md` 摘要、`Loaded skill: …` 这类系统文本仍是英文。

## 选项
| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 静态字典 `app/web/i18n/{en,zh,ko}.json` + HTML `data-i18n` + JS `t(key, vars)` | 零依赖、离线、可 diff、可让社区加语言 | 需要把散落字符串逐条抽出来（一次性人工） |
| B. 引入 i18next 等库 | 复数 / 插值成熟 | 多一个 vendor；本项目字符串量用不到 |
| C. 运行时让模型翻译界面 | 不用维护字典 | 每次启动花钱、慢、不确定 |

## 决定（提案）
A。具体：
1. **前端**：静态节点加 `data-i18n="key"`（`placeholder` / `title` 用 `data-i18n-attr`），运行时字符串走 `t()`；语言切换在 Settings 顶部，**不刷新页面**重渲染。
2. **持久化**：`ui.language` 存服务端 `<WORKSPACE>/.gisclaw/settings.json`（换浏览器不丢），`localStorage` 兜底；首次按 `navigator.language` 猜（`zh*`→zh，`ko*`→ko，其余 en）。
3. **后端消息改「码 + 参数」**：SSE `status` 与 HTTP 错误统一发 `{code, params, text}`，`text` 留英文兜底，前端按 `code` 查字典。服务端不持有任何语言状态。
4. **agent 文本**：`/api/run` 带上 `ui_lang`；closing note、`LOG.md` 摘要、意图闸门的拒绝语、`Loaded skill` 提示按 `ui_lang` 生成；正文回答仍跟随用户提问语言（用户用英文提问就英文答）。
5. **翻译来源**：zh 由作者写，ko 由作者复核后再合入（术语对齐 PDF 手册：图层 / 도형 / 속성 테이블 等）。
6. **回归**：selenium 三种语言各跑一遍主链路，0 个 JS 错误；界面截图不重做（README 截图保持英文）。

## 理由
字符串量在几百条量级，静态字典是最便宜且最稳的；把语言状态放在前端 + 用户设置，后端保持无状态，也不影响论文复现链。

## 结果
新增任何界面文本都必须走字典。以后加日文等语言只是多一个 JSON。
